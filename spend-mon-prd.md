# PRD: Spend-Mon Lite — First FastMCP Server + Agent Client

**Version:** 1.0 · **Author:** Abhi · **Status:** Draft · **Build target:** one evening (~3–4 focused hours)
**Position in roadmap:** Milestone 0 of Spend-Mon. Everything built here gets reused in the full project.

---

## 1. Overview

Spend-Mon Lite is a two-process system that exercises every concept learned so far in one coherent build:

1. **`spendlite_mcp`** — a FastMCP server exposing read-only expense tools over Streamable HTTP, backed by a seeded SQLite database, verified first with **MCP Inspector** (no LLM involved).
2. **`spendlite_agent`** — a terminal chat client built on the **OpenAI Agents SDK**, running **Gemini** through the OpenAI-compatible endpoint, that discovers and calls the MCP tools remotely. It layers on **token streaming**, a **local function tool**, an **input guardrail with structured output**, and **SQLiteSession** multi-turn memory.

The point of the split: prove the tools live in a different process than the model, connected only by a URL — the core boundary idea of Con-Mon, at the smallest possible scale.

## 2. Goals

1. Stand up a working FastMCP server with typed, Pydantic-validated tools and inspect it raw with MCP Inspector before any agent touches it.
2. Connect an Agents SDK agent to that server over Streamable HTTP and watch auto-discovered remote tool calls happen.
3. Exercise every prior learning in one place: async execution, Gemini-via-OpenAI-SDK, streaming deltas, typed stream events, local function tools, structured-output guardrails, and SDK session memory.
4. Ship it containerized with clear run/deploy steps that can be demoed to a senior engineer in under 5 minutes.
5. Total API cost: ₹0 (Gemini free tier only).

## 3. Non-Goals

- No FastAPI/SSE web endpoint and no browser UI (that is Milestone 1 of full Spend-Mon)
- No Postgres (SQLite keeps this to one evening; the SQL is written so it ports to Postgres unchanged)
- No auth, no multi-user, no write tools
- No production-grade deployment (a Dockerized local deploy plus an optional EC2 walk-through is the target)

## 5. Component spec: `spendlite_mcp`

### 5.1 Data (SQLite, generated by `seed.py`)

```sql
CREATE TABLE expenses (
    id         INTEGER PRIMARY KEY,
    spent_on   TEXT NOT NULL,      -- ISO date 'YYYY-MM-DD'
    amount_inr REAL NOT NULL CHECK (amount_inr > 0),
    category   TEXT NOT NULL,      -- food, transport, rent, shopping, subscriptions, health
    merchant   TEXT NOT NULL       -- Swiggy, Uber, Amazon, DMart, Netflix, ...
);
```

`seed.py` inserts ~200 randomized rows across March–June 2026, then prints per-month counts so seeding is verifiable at a glance.

### 5.2 Tools (all read-only)

| Tool                   | Inputs                                                              | Returns                               |
| ---------------------- | ------------------------------------------------------------------- | ------------------------------------- |
| `get_available_months` | —                                                                   | `[{month: "YYYY-MM", expense_count}]` |
| `list_categories`      | —                                                                   | `[category, ...]` derived from data   |
| `get_expenses`         | `month` (req), `category` (opt), `limit` (opt, default 20, max 100) | list of expense rows, newest first    |
| `get_category_summary` | `month` (req)                                                       | `[{category, total_inr, count}]`      |

Validation rules, enforced by Pydantic models in `schemas.py`:

1. `month` must match `^\d{4}-(0[1-9]|1[0-2])$` and parse as a real month; a bad value returns a structured error message, never a traceback.
2. Unknown `category` returns an error that lists the valid categories (gives the model a self-correction path).
3. Every tool docstring is written knowing it doubles as the tool description the LLM reads — one sentence on what it does, one on when to use it.

### 5.3 Server

```python
# server.py (shape, not full code)
from fastmcp import FastMCP
mcp = FastMCP("spendlite")

@mcp.tool
def get_available_months() -> list[MonthInfo]:
    """Return every month that has expense data, with row counts.
    Call this first to resolve 'latest' or 'last month'."""
    ...

if __name__ == "__main__":
    mcp.run(transport="http", host="0.0.0.0", port=8010)
```

Endpoint: `http://localhost:8010/mcp/`. DB path comes from `SPENDLITE_DB_PATH` env var (defaults to `./expenses.db`) — config via environment from day one, matching how the container is wired.

### 5.4 Verification with MCP Inspector (LLM-free gate)

Before writing any agent code:

```bash
npx @modelcontextprotocol/inspector
# Transport: Streamable HTTP → URL: http://localhost:8010/mcp/
```

Pass condition: Inspector lists all four tools with correct schemas; calling `get_category_summary` with `month=2026-06` returns data; calling it with `month=2026-13` returns the validation error, not a crash. **Do not proceed to the agent until this gate passes** — it separates "my tools are broken" from "my agent is broken" forever after.

## 6. Component spec: `spendlite_agent`

### 6.1 Model wiring (Gemini key, OpenAI packages)

```python
# model.py (shape)
from openai import AsyncOpenAI
from agents import OpenAIChatCompletionsModel, set_tracing_disabled

set_tracing_disabled(True)  # no OpenAI key, so no tracing backend

def build_model():
    client = AsyncOpenAI(
        api_key=os.getenv("GEMINI_API_KEY"),
        base_url="https://generativelanguage.googleapis.com/v1beta/openai/",
    )
    return OpenAIChatCompletionsModel(model="gemini-2.5-flash", openai_client=client)
```

One shared `build_model()` used by both the main agent and the guardrail agent.

### 6.2 Agent definition

- `Agent(name="SpendLiteAgent", instructions=<from instructions.txt>, model=build_model(), tools=[report_progress], mcp_servers=[spendlite_server], input_guardrails=[expense_topic_guardrail])`
- MCP connection: `MCPServerStreamableHttp(params={"url": SPENDLITE_MCP_URL})` used as an async context manager around the chat loop.
- **Local function tool** `report_progress(message: str)` — prints `[working] {message}` to the terminal; instructions tell the model to call it before looking anything up. This keeps the "local tool vs remote MCP tool" distinction alive in one codebase.

### 6.3 Instructions (`instructions.txt`) — required content

1. Answer only from tool results; never estimate amounts or invent merchants.
2. For "latest" / "last month" / "recently", call `get_available_months` first and use real months from its reply.
3. Refuse write requests, forecasting, and investment/financial advice; state briefly what is supported instead.
4. Always name the month(s) an answer covers; format amounts as ₹ with Indian digit grouping.
5. Never mention tools, MCP, schemas, or JSON to the user.

### 6.4 Input guardrail (structured output)

```python
class TopicCheck(BaseModel):
    is_off_topic: bool
    reasoning: str
```

A small guardrail agent (same Gemini model, `output_type=TopicCheck`) classifies whether the user message is about personal expenses/spending. Wired with the SDK's `@input_guardrail` decorator returning `GuardrailFunctionOutput(tripwire_triggered=check.is_off_topic, ...)`. The chat loop catches `InputGuardrailTripwireTriggered` and prints a polite redirect. Note for the demo: unlike the sequential check in learnings.md, the SDK runs this **in parallel** with the main run and cancels on tripwire — a latency win worth saying out loud.

### 6.5 Session memory

`SQLiteSession(session_id="local_chat", db_path="sessions.db")` passed to every `Runner.run_streamed` call. Acceptance behavior: asking "how much on food in June?" then "and transport?" works without restating the month. Restarting `chat.py` with the same `session_id` resumes context; `--new` flag starts a fresh session id.

### 6.6 Streaming chat loop

`chat.py` structure: `async def main()` under `asyncio.run(main())` (no top-level await), a `while True` input loop, and per turn:

```python
result = Runner.run_streamed(agent, user_input, session=session)
async for event in result.stream_events():
    if event.type == "raw_response_event" and isinstance(event.data, ResponseTextDeltaEvent):
        print(event.data.delta, end="", flush=True)
    elif event.type == "run_item_stream_event" and event.item.type == "tool_call_item":
        print(f"\n[tool] {event.item.raw_item.name}")
```

This reuses the typed-event pattern from learnings.md §4, but consuming the SDK's real event types instead of hand-rolled dataclasses.

### 6.7 Configuration (`.env.example`)

```env
GEMINI_API_KEY=your_key_here
SPENDLITE_MCP_URL=http://localhost:8010/mcp/
SPENDLITE_MODEL=gemini-2.5-flash
```

## 8. Deployment

### 8.1 Local containerized deploy (the demo default)

`spendlite_mcp/Dockerfile`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN python seed.py            # bake seeded db into the image (fine for a demo)
EXPOSE 8010
CMD ["python", "server.py"]
```

`docker-compose.yml`:

```yaml
services:
  spendlite-mcp:
    build: ./spendlite_mcp
    ports: ["8010:8010"]
    environment:
      SPENDLITE_DB_PATH: /app/expenses.db
    healthcheck:
      test:
        [
          "CMD",
          "python",
          "-c",
          "import urllib.request; urllib.request.urlopen('http://localhost:8010/mcp/', timeout=2)",
        ]
      interval: 10s
      retries: 3
```

Run: `docker compose up --build`, then point both Inspector and the agent at `http://localhost:8010/mcp/`. Key demo beat: the agent code did not change between "server via `python server.py`" and "server in a container" — only the URL matters.

### 8.2 Optional: EC2 deploy (10-minute stretch, plays to the AWS background)

1. t3.micro Ubuntu instance; security group allows port 8010 **only from your own IP** (call this restriction out — an open MCP port is an open tool API).
2. `sudo apt install docker.io docker-compose-plugin`, clone repo, `docker compose up -d`.
3. On the laptop: set `SPENDLITE_MCP_URL=http://<ec2-public-ip>:8010/mcp/` and run `chat.py` unchanged.
4. Demo line: "local agent, cloud tools — same code, different env var." Tear the instance down after.

## 9. Acceptance criteria

1. MCP Inspector connects, lists 4 tools, valid calls succeed, `month=2026-13` returns a structured validation error.
2. `chat.py` streams answers token-by-token with `[tool]` lines showing remote MCP calls and `[working]` lines from the local tool.
3. "How much did I spend on food in June 2026?" returns the correct total (cross-check with a direct SQL query).
4. "What's my latest month?" triggers `get_available_months` — the agent never guesses a month.
5. Follow-up "and transport?" works via session memory; `--new` starts clean.
6. "Should I invest in stocks?" trips the guardrail and prints a redirect, not an answer.
7. "Add ₹500 chai expense" is refused per instructions (no write tools exist anyway — defense in two layers).
8. Whole stack runs with the MCP server in Docker; agent untouched.

## 10. Demo script for the senior (≤5 min)

1. `docker compose up` → healthcheck green.
2. MCP Inspector → list tools → call `get_category_summary(month="2026-06")` raw. _"This process owns the data. No model involved yet."_
3. Run `chat.py` → ask acceptance question 3, point out `[working]`, `[tool]`, and streaming.
4. Ask the follow-up ("and transport?") → session memory.
5. Ask the guardrail question → tripwire redirect.
6. Close: _"This is Milestone 0 of a full Spend-Mon build — next I'm adding a FastAPI SSE layer and normalized events like Con-Mon's run stream. I'd also like to pick up a small Con-Mon task when there's one going."_
